# 01 - التقسيم والتخطيط الدلالي في HTML5 (Semantic Layout)

> 🌐 **Language / اللغة:** [English 🇬🇧](../en/01-semantic-html5-layout.md) | [العربية 🇸🇦](./01-semantic-html5-layout.md)

## 📌 1. ما وراء وسوم `<div>`: الويب الدلالي الحديث

قبل صدور معيار HTML5، كان المطورون يبنون صفحات الويب بالكامل باستخدام وسوم `<div>` عامة مع أسماء فئات عشوائية (`<div id="nav">`، `<div class="footer">`). ولكن بالنسبة لمحركات البحث وقارئات الشاشة للمكفوفين، فإن وسم `<div>` **لا يحمل أي معنى دلالي على الإطلاق**—فهو مجرد حاوية تنسيق فارغة.

جاءت HTML5 بمجموعة وسوم هيكلية دلالية (Semantic Landmarks) حولت الصفحة إلى شجرة منظمة وواضحة المعالم:

```
┌────────────────────────────────────────────────────────────┐
│                        <header>                            │
│  ┌──────────────────────────────────────────────────────┐  │
│  │                       <nav>                          │  │
│  └──────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────┬─────────────┐
│                   <main>                     │   <aside>   │
│  ┌────────────────────────────────────────┐  │  (شريط جانبي│
│  │               <section>                │  │  محتوى فرعي)│
│  │  ┌──────────────────┐ ┌─────────────┐  │  │             │
│  │  │    <article>     │ │  <article>  │  │  │             │
│  │  └──────────────────┘ └─────────────┘  │  │             │
│  └────────────────────────────────────────┘  │             │
└──────────────────────────────────────────────┴─────────────┘
┌────────────────────────────────────────────────────────────┐
│                        <footer>                            │
└────────────────────────────────────────────────────────────┘
```

## 🏗️ 2. وسوم التقسيم الهيكلية الدلالية

### أ. ترويسة الصفحة أو القسم (`<header>`)
تمثل المحتوى التمهيدي أو مجموعة روابط التنقل للقسم أو للصفحة ككل. تحتوي عادةً على شعار الموقع (Logo)، شريط البحث، وقائمة التنقل الرئيسية.

### ب. شريط التنقل الرئيسي (`<nav>`)
يحدد القسم المخصص حصرياً لروابط التنقل الأساسية في الموقع. تتيح برمجيات قارئات الشاشة للمستخدمين القفز مباشرة إلى `<nav>` أو تخطيه للوصول للمحتوى.

### ج. المحتوى الرئيسي الفريد (`<main>`)
يحتوي على **المحتوى الجوهري والفريد** للمستند الحالي.
- **قاعدة صارمة:** يُسمح بوجود عنصر `<main>` **واحد فقط** ظاهر في كل صفحة. ولا يجوز أن يتضمن روابط متكررة في كل الصفحات (مثل تذييل الموقع أو أشرطة التنقل).

### د. الفرق بين `<section>` و `<article>` (الفارق الهندسي الهام):
- **`<article>`:** يمثل **وحدة محتوى مستقلة بذاتها** يمكن نظرياً نشرها أو قراءتها أو مشاركتها بمفردها خارج سياق الصفحة (مثل: مقال مدونة، خبر صحفي، بطاقة منتج، تعليق مستخدم).
- **`<section>`:** يمثل **تجميعاً دلالياً لموضوع محدد** داخل الصفحة، ويحتوي غالباً على عنوان خاص به (مثل: قسم "المميزات"، قسم "الأسعار"، قسم "آراء العملاء").

### هـ. المحتوى الجانبي المساعد (`<aside>`)
يحتوي على معلومات ترتبط بالمحتوى المحيط بشكل فرعي غير أساسي (مثل: الشريط الجانبي Sidebar، روابط المقالات ذات الصلة، صناديق التعريف بالمصطلحات).

### و. تذييل الصفحة (`<footer>`)
يحتوي على البيانات الختامية: حقوق النشر، روابط سياسة الخصوصية، معلومات التواصل وروابط الشروط والأحكام.

---

## ♿ 3. فوائد الدلالات لمحركات البحث (SEO) وقارئات الشاشة

1. **معالم التنقل (Screen Reader Landmarks):** توفر قارئات الشاشة اختصارات تمكن الكفيف من القفز مباشرة إلى `<main>` دون إجباره على سماع كامل روابط الترويسة في كل زيارة.
2. **فهم محركات البحث:** تعطي محركات بحث جوجل أولوية فهرسة عظمى للنصوص داخل `<main>` و`<article>` وتتجاهل النصوص التكرارية في التذييل.

---

## 🎯 ملخص وتحدي الدرس

- استبدل الحاويات العمياء `<div>` بالوسوم الدلالية المحددة.
- عنصر `<article>` مستقل وقائم بذاته؛ بينما `<section>` يجمع فقرات موضوع متجانس.
- عنصر `<main>` واحد فقط في الصفحة.

**تحدي الدرس:** أعد هيكلة صفحة مدونة شخصية باستخدام `<header>`، `<nav>`، `<main>` يضم بطاقتي مقال `<article>` داخل `<section>`، شريطاً جانبياً `<aside>`، وتذييل `<footer >`.
