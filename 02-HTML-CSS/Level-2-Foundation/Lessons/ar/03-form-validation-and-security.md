> 🌐 **Language / اللغة:** [English 🇬🇧](../en/03-form-validation-and-security.md) | [العربية 🇸🇦](./03-form-validation-and-security.md)

## 📌 1. قيود التحقق الأصلية في HTML5 (Constraint Validation)

قبل HTML5، كان فحص صحة المدخلات يتطلب كتابة أكواد جافا سكريبت مطولة. وفرت HTML5 خصائص فحص برمجية أصلية مدمجة في المتصفح مباشرة:

```html
<form action="/api/register" method="POST">
    <!-- حقل إلزامي مع قيود نمطية -->
    <label for="username">اسم المستخدم (أحرف وأرقام فقط، من 4 إلى 16 محرف):</label>
    <input type="text" 
           id="username" 
           name="username" 
           required 
           minlength="4" 
           maxlength="16" 
           pattern="[a-zA-Z0-9_]+" 
           title="يُسمح بالأحرف الإنجليزية والأرقام والشرطة السفلية فقط.">

    <!-- التحقق من صيغة البريد -->
    <label for="email">البريد الإلكتروني للعمل:</label>
    <input type="email" id="email" name="email" required>

    <!-- قيود النطاق الرقمي -->
    <label for="age">المستوى الأمني (من 1 إلى 5):</label>
    <input type="number" id="age" name="clearance" min="1" max="5" value="1">

    <button type="submit">إرسال الطلب</button>
</form>
```

### خصائص التحقق الجوهرية:
- **`required`:** يمنع إرسال النموذج إذا كان الحقل فارغاً.
- **`pattern="regex"`:** يفحص القيمة بناءً على تعبير نمطي (Regular Expression).
- **`minlength` / `maxlength`:** يحدد الحد الأدنى والأقصى لعدد الأحرف.
- **`min` / `max` / `step`:** يحدد الحدود الرقمية والتواريخ.

## 🎨 2. تنسيق حالات التحقق عبر فئات CSS الزائفة

يمكنك تلوين وتنسيق الحقول ديناميكياً أثناء تفاعل المستخدم:

```css
/* إبراز الحقول الإلزامية */
input:required {
    border-left: 3px solid #0284c7;
}

/* الفئة الحديثة: تتفعل فقط بعد محاولة تفاعل المستخدم لتجنب إزعاجه */
input:user-invalid {
    border-color: #ef4444;
    background-color: #fef2f2;
}

input:user-valid {
    border-color: #10b981;
}
```

## 🛡️ 3. المفارقة الأمنية الكبرى: الفحص في المتصفح مقابل الفحص في السيرفر

> ⚠️ **القاعدة الذهبية في أمان الويب:** **التحقق من صحة البيانات في المتصفح مخصص حصرياً لتحسين تجربة المستخدم (UX)، ولا يُعتد به نهائياً كحماية أمنية (Security)!**

```
 [ المتصفح / العميل ]                                   [ خادم الويب / السيرفر ]
 ┌──────────────────────┐                             ┌──────────────────────┐
 │ قيود HTML5:          │                             │ المنطق البرمجي الصارم│
 │  required, pattern   │ ────(Burp Suite / curl)────►│ يجب إعادة فحص        │
 │ (يمكن للمهاجم حذفها  │  (تخطي كامل لقيود المتصفح)  │ كل حقل إدخال 100%    │
 │  في ثانية واحدة!)     │                             │                      │
 └──────────────────────┘                             └──────────────────────┘
```

### كيف يتخطى المخترقون قيود المتصفح؟
1. **أدوات المطور (DevTools):** فتح أداة الفحص وحذف خاصية `required` أو `pattern` من كود HTML بضغطة زر.
2. **اعتراض الطلبات (Burp Suite):** كتابة بيانات مقبولة في المتصفح، واعتراض طلب الـ HTTP POST وتغيير القيم إلى أكواد حقن خبيثة قبل وصولها للسيرفر.
3. **الطلبات المباشرة:** إرسال الطلب برمجياً عبر `curl` أو بايثون مباشرة إلى السيرفر متجاوزاً المتصفح بأكمله.

**الخلاصة الأمنية:** يجب فحص وتنقية وتعقيم كافة البيانات القادمة في السيرفر دون الاعتماد مطلقاً على قواعد المتصفح.

## 🔑 4. حماية الإكمال التلقائي وخاصية `autocomplete`

تحفظ المتصفحات الحديثة كلمات المرور والبطاقات الائتمانية للإكمال التلقائي. تحديد سياق الحقول يمنع تسريب البيانات:

```html
<!-- تعريف صريح لبيانات الدخول -->
<input type="text" name="username" autocomplete="username">
<input type="password" name="password" autocomplete="current-password">

<!-- إنشاء كلمة مرور جديدة (يمنع اقتراح كلمات المرور القديمة) -->
<input type="password" name="new-password" autocomplete="new-password">

<!-- رمز التحقق بخطوتين (2FA OTP) -->
<input type="text" name="otp" autocomplete="one-time-code" inputmode="numeric">

<!-- تعطيل الإكمال التلقائي للرموز الحساسة ومفاتيح API -->
<input type="text" name="api-key" autocomplete="off">
```

## 🎯 ملخص وتحدي الدرس

- استخدم قيود HTML5 لتقديم تغذية راجعة فورية للمستخدم.
- نسق الأخطاء عبر `:user-invalid`.
- إياك والاعتماد على المتصفح لمنع الهجمات، فالسيرفر هو خط الدفاع الحقيقي.
- حدد سياق `autocomplete` لحماية خصوصية بيانات المستخدمين.

**تحدي الدرس:** أنشئ نموذج إعادة تعيين كلمة المرور يضم: `كلمة المرور الحالية`، `كلمة المرور الجديدة` (بحد أدنى 8 محارف ورقم عبر `pattern`)، وخاصية `autocomplete`. جرب حذف القيود من أدوات المطور (F12) لتشاهد كيف يتخطى المهاجم فحص المتصفح.
