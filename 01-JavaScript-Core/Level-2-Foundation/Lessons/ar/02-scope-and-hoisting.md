## 🎯 1. نظرة عامة وأهداف التعلم (Overview & Learning Objectives)

تعد الأخطاء الناتجة عن سوء فهم كيفية تعامل محرك جافا سكريبت مع رؤية المتغيرات (Scope) وتخصيص الذاكرة والرفع (Hoisting) من أكثر الأخطاء الخفية شيوعاً في تطبيقات الويب.

بنهاية هذا الدرس، ستتقن:
1. المستويات الثلاثة لنطاقات المتغيرات في جافا سكريبت: **العام (Global)**، **الدالة (Function)**، و **الكتلة البرمجية (Block)**.
2. كيف يبحث محرك جافا سكريبت عن المتغيرات عبر **سلسلة النطاقات (Scope Chain)**.
3. الفروق الجوهرية والتقنية الدقيقة بين `var` و `let` و `const`.
4. آلية عمل **الرفع (Hoisting)** خلال مرحلتي الإنشاء والتنفيذ.
5. مفهوم **منطقة الخمول الزمني (Temporal Dead Zone - TDZ)** وسبب حدوث خطأ `ReferenceError`.
6. أفضل ممارسات كتابة الكود النظيف للإعلان عن المتغيرات.

## 🌐 2. المستويات الثلاثة لنطاقات المتغيرات (The 3 Tiers of Scope)

يحدد النطاق (Scope) الأماكن التي يمكن فيها الوصول إلى المتغير أو الدالة واستخدامها داخل الكود البرمجي.

```
+-------------------------------------------------------------+
| 1. النطاق العام (GLOBAL SCOPE)                              |
|    متاح في كل مكان عبر بيئة التشغيل بالكامل                 |
|                                                             |
|    +---------------------------------------------------+    |
|    | 2. نطاق الدالة (FUNCTION SCOPE)                   |    |
|    |    محصور حصراً داخل جسم الدالة                    |    |
|    |                                                   |    |
|    |    +-----------------------------------------+    |    |
|    |    | 3. نطاق الكتلة البرمجية (BLOCK SCOPE)   |    |    |
|    |    |    محصور بدقة داخل الأقواس { ... }      |    |    |
|    |    +-----------------------------------------+    |    |
|    +---------------------------------------------------+    |
+-------------------------------------------------------------+
```

### 1. النطاق العام (Global Scope)
المتغيرات المعلنة خارج أي دالة أو كتلة برمجية تعيش في النطاق العام. في المتصفح، يؤدي استخدام `var` في النطاق العام إلى إضافته كخاصية مباشرة على كائن `window`:
```javascript
var appName = 'ShopApp';
console.log(window.appName); // 'ShopApp' (يلوث كائن window العام!)

const apiKey = 'SECRET_123';
console.log(window.apiKey);  // undefined (المتغيران let و const لا يلوثان كائن window)
```

### 2. نطاق الدالة (Function Scope)
المتغيرات المعلنة داخل دالة لا يمكن الوصول إليها من خارجها:
```javascript
function initSession() {
  var sessionId = 'sess_9941';
  let token = 'xyz_token';
}
initSession();
// console.log(sessionId); // Uncaught ReferenceError: sessionId is not defined
```

### 3. نطاق الكتلة البرمجية (Block Scope)
أي زوج من الأقواس المعقوفة `{ ... }` (في جمل `if` أو حلقات `for` أو الكتل البرمجية المجردة) يشكل نطاق كتلة برمجية. **المتغيران `let` و `const` يحترمان نطاق الكتلة، بينما يتجاهله `var` تماماً!**
```javascript
if (true) {
  var leakedVar = 'أستطيع الهروب من الكتلة البرمجية!';
  let scopedLet = 'أنا محبوس داخل هذه الأقواس فقط';
  const scopedConst = 'وأنا أيضاً محبوس';
}

console.log(leakedVar);   // 'أستطيع الهروب...' (var يتجاهل كتل if/for!)
// console.log(scopedLet); // Uncaught ReferenceError: scopedLet is not defined
```

## 🔗 3. سلسلة النطاقات والحل المعجمي (Scope Chain & Lexical Resolution)

تستخدم جافا سكريبت أسلوب **النطاق المعجمي (Lexical Scoping)**، مما يعني أن نطاق المتغير يتحدد بمكان كتابته الفعلي في الكود المصدري أثناء البرمجة.

عندما يحاول المحرك قراءة قيمة متغير:
1. يبحث أولاً في النطاق المحلي المباشر.
2. إذا لم يعثر عليه، يصعد درجة إلى النطاق الحاوي الأب (Parent Scope).
3. يكرر الصعود خطوة بخطوة حتى يصل إلى النطاق العام (Global Scope).
4. إذا لم يعثر عليه في أي مكان، يرمي المتصفح خطأ `ReferenceError`.

```javascript
const globalGreeting = 'أهلاً';

function outer() {
  const outerName = 'محمد';

  function inner() {
    const innerTitle = 'مهندس برمجيات';
    // يصعد المحرك من الداخل إلى الخارج:
    console.log(`${globalGreeting} يا ${outerName} (${innerTitle})`);
  }

  inner();
}
outer(); // "أهلاً يا محمد (مهندس برمجيات)"
```

## 🏗️ 4. الرفع (Hoisting): مرحلة الإنشاء مقابل مرحلة التنفيذ

عندما يبدأ محرك جافا سكريبت (مثل V8) بتشغيل ملف السكربت، فإنه لا ينفذ السطر الأول فوراً، بل يعمل عبر **مرحلتين**:

```
المرحلة 1: مرحلة الإنشاء وحجز الذاكرة (Creation Phase)
- حجز مساحة في الذاكرة لتصريحات الدوال (Function Declarations).
- حجز مساحة للمتغيرات (var يتم تعيين قيمته كـ undefined؛ بينما let/const يظلان بدون تهيئة).

المرحلة 2: مرحلة التنفيذ الفعلي (Execution Phase)
- قراءة وتنفيذ الكود سطراً بسطر من الأعلى إلى الأسفل.
- تقييم التعبيرات وتعيين القيم الحقيقية للمتغيرات.
```

### أ) رفع تصريحات الدوال (Function Declaration Hoisting)
تُرفع الدوال المصرح بها بشكل كامل مع جسمها البرمجي إلى أعلى النطاق:
```javascript
// يعمل هذا الكود بنجاح تام وبدون أي أخطاء:
greetUser('حسن'); // "مرحباً يا حسن!"

function greetUser(name) {
  console.log(`مرحباً يا ${name}!`);
}
```

### ب) تعبيرات الدوال والدوال السهمية لا تُرفع كدوال
نظراً لأنها تُسند إلى متغيرات، فإنها تتبع قواعد رفع المتغيرات:
```javascript
// TypeError: sayHi is not a function
sayHi(); 

var sayHi = function() {
  console.log('مرحباً!');
};
```

## 🚫 5. منطقة الخمول الزمني (Temporal Dead Zone - TDZ)

من المفاهيم الخاطئة الشائعة الاعتقاد بأن `let` و `const` لا يحدث لهما رفع (Hoisting). **في الواقع، يتم رفعهما**، لكن خلافاً لـ `var`، لا يتم إسناد القيمة `undefined` لهما أثناء مرحلة الإنشاء.

الفترة الزمنية الممتدة من لحظة الدخول إلى النطاق وحتى الوصول إلى السطر البرمجي الذي تم فيه الإعلان عن المتغير تُعرف باسم **منطقة الخمول الزمني (TDZ)**.

```javascript
{
  // <---- تبدأ منطقة الخمول الزمني (TDZ) للمتغير username هنا
  // console.log(username); // ❌ Uncaught ReferenceError: Cannot access 'username' before initialization
  
  const greeting = 'أهلاً'; // المتغير username ما زال في منطقة الخمول
  
  let username = 'أحمد';   // <---- تنتهي منطقة الـ TDZ هنا! تمت التهيئة بالقيمة 'أحمد'
  console.log(username);  // ✅ 'أحمد'
}
```

### جدول مقارنة شامل: `var` مقابل `let` مقابل `const`

| الميزة | `var` | `let` | `const` |
| :--- | :---: | :---: | :---: |
| **حدود النطاق** | نطاق الدالة (Function Scope) | نطاق الكتلة `{}` (Block Scope) | نطاق الكتلة `{}` (Block Scope) |
| **سلوك الرفع (Hoisting)** | يُرفع وتهيأ قيمته بـ `undefined` | يُرفع داخل منطقة الخمول **TDZ** | يُرفع داخل منطقة الخمول **TDZ** |
| **إعادة الإعلان في نفس النطاق** | مسموح به (قد يسبب أخطاء خفية) | ممنوع قطيعاً (`SyntaxError`) | ممنوع قطيعاً (`SyntaxError`) |
| **إعادة الإسناد وتغيير القيمة** | مسموح به | مسموح به | ممنوع قطيعاً (`TypeError`) |
| **الارتباط بكائن `window` العام** | نعم (`window.x`) | لا | لا |

## 🧼 6. مقارنة الكود النظيف (Clean Code: Good vs Bad)

```javascript
// ❌ كود سيئ: استخدام var والاعتماد على غموض الرفع وتسريب المتغيرات
function calculateTotal(items) {
  var total = 0;
  for (var i = 0; i < items.length; i++) {
    var discount = 5;
    total += items[i] - discount;
  }
  console.log(i); // 3 (تسرب متغير العداد خارج حلقة التكرار!)
  return total;
}

// ✅ كود ممتاز: استخدام const كأساس، و let للعداد، مع عزل النطاقات بدقة
function calculateTotal(items) {
  const DISCOUNT = 5;
  let total = 0;

  for (let i = 0; i < items.length; i++) {
    total += items[i] - DISCOUNT;
  }
  // console.log(i); // ReferenceError: المتغير i محصور بأمان داخل حلقة for فقط
  return total;
}
```

## 📝 7. الخلاصة والدرس التالي
- فضل دائماً استخدام **`const`** لأي متغير ثابت القيمة، واستخدم **`let`** فقط عند الحاجة لتغيير القيمة.
- **تجنب استخدام `var` نهائياً** في المشاريع الحديثة لمنع تسريب المتغيرات والالتباس البرمجي.
- فهم **منطقة الخمول الزمني (TDZ)** يحميك من استدعاء المتغيرات قبل تهيئتها.
- في الدرس التالي، سنشرح **الكائنات والمراجع في الذاكرة والنسخ السطحي والعميق (Objects, References & Memory Pointers)**.
