## 🎯 1. نظرة عامة وأهداف التعلم (Overview & Learning Objectives)

يعتمد المطور المبتدئ بشكل شبه كامل على كتابة عبارات `console.log()` في كل مكان لتتبع الأخطاء. في المقابل، يعتمد مهندس البرمجيات المحترف ومختبر الاختراق على **أدوات المطور المدمجة في المتصفح (DevTools)** لإيقاف التنفيذ لحظياً، وتتبع مكدس الاستدعاءات (Call Stack)، وفحص متغيرات الذاكرة، واعتراض حركة مرور الشبكة مباشرة أثناء التشغيل.

بنهاية هذا الدرس، ستتقن:
1. استغلال واجهة **Console API** المتقدمة: `console.table()` و `console.time()` و `console.trace()`.
2. إتقان وضع نقاط التوقف التفاعلية: **العادية (Line-of-code)**، **الشرطية (Conditional)**، ونقاط التسجيل **(Logpoints)**.
3. مراقبة تعديلات الـ DOM واعتراض طلبات الشبكة بنقاط توقف **XHR/Fetch Breakpoints**.
4. التحكم في مسار التنفيذ: تجاوز الدوال (Step Over)، الدخول داخلها (Step Into)، والخروج منها (Step Out).
5. إجراء الفحص الجنائي لحركة مرور البيانات ومحاكاة بطء الشبكة في لوحة **Network**.
6. تنظيف الأكواد من مخلفات الفحص المؤقتة تلقائياً عبر قواعد **ESLint**.

## 🖥️ 2. أدوات الكونسول المتقدمة واختصارات سطر الأوامر

توفر أدوات المطور دوالاً تتجاوز بمراحل مجرد الطباعة النصية البسيطة:

```javascript
// 1. console.table(): عرض المصفوفات والكائنات في جدول منظم وأنيق:
const users = [
  { id: 1, name: 'أحمد', role: 'Dev', score: 95 },
  { id: 2, name: 'سارة', role: 'Designer', score: 88 }
];
console.table(users);

// 2. console.time() و console.timeEnd(): قياس زمن تنفيذ العمليات البرمجية بدقة متناهية:
console.time('مؤقت الخوارزمية');
for (let i = 0; i < 1000000; i++) { /* معالجة حسابية */ }
console.timeEnd('مؤقت الخوارزمية'); // الناتج: "مؤقت الخوارزمية: 3.42ms"

// 3. console.trace(): طباعة مكدس الاستدعاءات الكامل (Call Stack) الذي قاد لهذا السطر:
function deepFunction() {
  console.trace('من أين تم استدعاء دالة deepFunction؟');
}
deepFunction();
```

### اختصارات سطر أوامر DevTools السريعة:
- **`$0`:** يُرجع عنصر الـ DOM المحدد حالياً في تبويب **Elements**.
- **`$$('selector')`:** اختصار مدمج يعادل `Array.from(document.querySelectorAll('selector'))`.
- **`$_`:** يُرجع ناتج آخر أمر تم تنفيذه في الـ Console.
- **`monitor(functionName)`:** يطبع إشعاراً في الـ Console مع المعاملات في كل مرة يتم فيها استدعاء تلك الدالة.

## 🛑 3. تبويب Sources: احتراف نقاط التوقف (Breakpoints)

بدلاً من تعديل الملفات وحفظها لإضافة `console.log`، افتح تبويب **Sources** (`F12` أو `Ctrl+Shift+I`):

```
+-----------------------------------------------------------------------------------+
| لوحة SOURCES في المتصفح                                                           |
+-----------------------------------------------------------------------------------+
|  [ السطر 42 ] const total = calculatePrice(cart);  <=== [ علامة زرقاء: Breakpoint ]|
|  [ السطر 43 ] displayTotal(total);                                                |
|                                                                                   |
|  أزرار التحكم في سير التنفيذ:                                                     |
|  [ ▶ | F8 ]  مواصلة التشغيل حتى نقطة التوقف التالية (Resume)                     |
|  [ ↷ | F10] تخطي السطر الحالي والانتقال للتالي دون دخول تفاصيل الدالة (Step Over)  |
|  [ ↧ | F11] الدخول داخل الدالة المنفذة في هذا السطر (Step Into)                   |
|  [ ↥ | ⇧F11] الخروج من الدالة الحالية والعودة للمستدعي (Step Out)                 |
+-----------------------------------------------------------------------------------+
```

### أنواع نقاط التوقف:

#### 1. نقطة التوقف العادية (Line-of-Code Breakpoint)
انقر مباشرة على رقم السطر في محرر الأكواد داخل تبويب Sources؛ يتجمد المتصفح في اللحظة التي يصل فيها التنفيذ لذلك السطر.

#### 2. الكلمة المفتاحية `debugger;`
ضع الكلمة المفتاحية `debugger;` في كود الجافا سكريبت الخاص بك. إذا كانت أدوات المطور مفتوحة، سيتجمد المتصفح تلقائياً عند هذا السطر:
```javascript
function processTransaction(transaction) {
  if (transaction.amount > 10000) {
    debugger; // يتوقف المتصفح تلقائياً هنا لمعاينة المتغيرات في الحالات المشبوهة!
  }
}
```

#### 3. نقاط التوقف الشرطية (Conditional Breakpoints)
انقر بزر الفأرة الأيمن على رقم السطر ➔ **Add conditional breakpoint...**:
```javascript
// لا يتوقف المتصفح إلا إذا تحقق هذا الشرط وأرجع true:
user.role === 'admin' && user.id === 94
```

#### 4. نقاط التسجيل (Logpoints)
انقر بزر الفأرة الأيمن ➔ **Add logpoint...**:
تطبع قيمة متغير في الـ Console **دون إيقاف المتصفح** ودون الحاجة لتعديل الكود المصدري الأصلي.

## ⚡ 4. نقاط التوقف المتخصصة: الـ DOM، الشبكة، والأحداث

تستطيع أدوات المطور إيقاف التنفيذ تلقائياً عند وقوع أحداث خارجية معينة:

### أ) نقاط توقف تعديلات الـ DOM (DOM Breakpoints)
في تبويب **Elements**، انقر بزر الفأرة الأيمن على أي وسم ➔ **Break on**:
- **Subtree modifications:** يتوقف عند إضافة أو حذف عناصر ابن.
- **Attribute modifications:** يتوقف عند تغيير أي كلاس أو نمط أو سمة.
- **Node removal:** يتوقف عند حذف العنصر نفسه من الصفحة.

### ب) نقاط توقف طلبات الشبكة (XHR / Fetch Breakpoints)
في الشريط الجانبي الأيمن لتبويب Sources ➔ افتح قسم **XHR/fetch Breakpoints**:
- أضف جزءاً من الرابط (مثل `/api/orders`).
- سيتوقف المتصفح تلقائياً عند السطر البرمجي الذي أطلق الـ `fetch()` لهذا الرابط فوراً!

### ج) نقاط توقف مستمعي الأحداث (Event Listener Breakpoints)
في الشريط الجانبي ➔ افتح **Event Listener Breakpoints**:
- حدد **Mouse** ➔ **click**.
- سيتوقف المتصفح تلقائياً داخل الدالة المعالجة للنقرة القادمة في أي مكان بالصفحة!

## 🌐 5. الفحص الجنائي لشبكة الاتصال (Network Tab Forensics)

تسجل لوحة **Network** كل طلب واستجابة HTTP تتم بين المتصفح والخادم:

```
اسم المورد            الحالة    النوع    الحجم      الوقت     الشلال الزمني
---------------------------------------------------------------------------
/api/auth/login      200      xhr      842 B    120 ms   [====]
/static/js/main.js   304      script   45.2 kB  15 ms    [=]
/api/analytics       500      fetch    1.2 kB   450 ms   [================]
```

### ميزات احترافية هامة في لوحة Network:
1. **محاكاة بطء الشبكة (Network Throttling):** تغيير القائمة من **No throttling** إلى **Fast 3G** أو **Slow 3G** أو **Offline** لاختبار تجربة المستخدم عند ضعف الاتصال.
2. **تعطيل الذاكرة المؤقتة (Disable Cache):** تفعيل خيار **Disable cache** لضمان تنزيل أحدث نسخة من ملفات الجافا سكريبت دائماً أثناء التطوير.
3. **النسخ كطلب cURL أو fetch:** انقر بزر الفأرة الأيمن على أي طلب شبكة ➔ **Copy** ➔ **Copy as cURL** لإعادة تشغيل الطلب في الطرفية أو أدوات الاختبار.

## 🧼 6. مقارنة الكود النظيف (Clean Code: Good vs Bad)

```javascript
// ❌ كود سيئ: ترك عبارات console.log و debugger في بيئة الإنتاج الحية
function checkout() {
  console.log('entering checkout');
  console.log('cart contents:', cart);
  debugger; // كارثة: أي مستخدم يفتح DevTools سيتجمد موقعه فوراً!
  submitOrder();
}

// ✅ كود ممتاز: إزالة عبارات التصحيح تماماً واستخدام فاحص آلي
function checkout() {
  submitOrder();
}
```

### قواعد الفحص الآلي الموصى بها في ESLint:
أضف هذه القواعد في ملف التكوين `.eslintrc.json`:
```json
{
  "rules": {
    "no-console": "warn",
    "no-debugger": "error"
  }
}
```

## 📝 7. الخلاصة والدرس التالي
- استخدم **`console.table()`** و **`console.time()`** لعرض البيانات المعقدة وقياس الأداء.
- استخدم **نقاط التوقف الشرطية** ونقاط **Logpoints** بدلاً من تلويث الكود بـ `console.log`.
- راقب متى تتغير عناصر الصفحة أو تُرسل الطلبات بنقاط توقف **DOM** و **XHR Breakpoints**.
- اختبر سرعة واستجابة تطبيقك عبر ميزة **محاكاة سرعة الشبكة (Throttling)**.
- احرص على حظر `debugger` في أدوات الفحص الآلي (Linter) قبل رفع الكود.
- في الدرس الأخير من المستوى الثاني، سنتعلم حجر الأساس لأمان الويب: **أساسيات أمان المتصفح وسياسة الأصل المشترك (SOP, CORS & Trust Boundaries)**.
