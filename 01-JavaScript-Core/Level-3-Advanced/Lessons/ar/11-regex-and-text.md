## 🎯 1. نظرة عامة وأهداف التعلم (Overview & Learning Objectives)

تُعد التعابير النمطية (Regular Expressions - RegExp) من أقوى الأدوات في ترسانة مطور جافاسكريبت، وفي نفس الوقت من أكثرها خطورة إذا أسيء استخدامها. فبينما لا غنى عنها في تحليل النصوص، واستخراج الرموز، والتحقق من صحة المدخلات، فإن الأنماط الرديئة أو غير المنضبطة قد تؤدي لظاهرة **التراجع الكارثي (Catastrophic Backtracking)**، مما ينتج عنه ثغرة حجب الخدمة **(ReDoS - Regular Expression Denial of Service)** التي تجمد خيط معالجة V8 الفردي وتوقف خوادم وتطبيقات الويب عن العمل تماماً.

بنهاية هذا الدرس، ستتقن تماماً:
1. الميكانيكية الداخلية لمحرك التراجع الآلي **NFA (Nondeterministic Finite Automaton)** في جافاسكريبت.
2. أدوات الفحص المحيطي المتقدمة (Lookaround Assertions): **Lookaheads** (`(?=...)`, `(?!...)`) و **Lookbehinds** (`(?<=...)`, `(?<!...)`).
3. مميزات معايير ES الحديثة: **المجموعات المسماة (Named Capture Groups)**، مؤشرات المطابقة (`/d`)، وعلم اليونيكود المتقدم (`/v`).
4. تشخيص واحتساب والقضاء على ثغرات **التراجع الكارثي (ReDoS)** وحماية خوادم Node.js والمتصفح.
5. استخراج البيانات ومعالجة النصوص المتقدمة باستخدام `String.prototype.matchAll()` ودوال الاستبدال الآمنة.

## 🧠 2. محرك NFA والأعلام الحديثة (Modern RegExp Flags)

يعتمد محرك جافاسكريبت على خوارزمية **NFA**. عندما يواجه المحرك مسارات متعددة (مثل الخيارات `a|b` أو التكرارات `*` و `+`)، فإنه يلتهم الحروف بنهم (Greedy). وفي حال فشل مطابقة الرموز التالية، يقوم المحرك بـ **التراجع (Backtracking)** إلى نقطة الاختيار السابقة لتجربة مسار بديل.

### أعلام التعابير النمطية الحديثة (Modern Flags):
| العلم (Flag) | المعنى | الإصدار | أبرز حالات الاستخدام |
| :--- | :--- | :--- | :--- |
| **`g`** | عام (Global) | ES3 | البحث عن كافة المطابقات في النص بدلاً من التوقف عند أول واحدة. |
| **`i`** | تجاهل حالة الأحرف | ES3 | مطابقة الحروف الكبيرة والصغيرة دون تمييز. |
| **`m`** | متعدد الأسطر (Multiline) | ES3 | جعل `^` و `$` يطابقان بداية ونهاية كل سطر مستقل. |
| **`s`** | شمول النقاط (DotAll) | ES2018 | جعل الرمز `.` يطابق حتى أحرف الأسطر الجديدة (`\n`, `\r`). |
| **`u`** | اليونيكود الكامل | ES2015 | التعامل الصحيح مع الرموز التعبيرية (Emojis) والحروف متعددة البايتات. |
| **`v`** | مجموعات اليونيكود | ES2024 | ترقية لعلم `u` لدعم عمليات تقاطع المجموعات وطرح الخصائص النصية. |
| **`d`** | استخراج المؤشرات | ES2022 | توليد أرقام بداية ونهاية كل مطابقة نصية داخل `match.indices`. |

## 🔍 3. الفحص المحيطي المتقدم (Lookaheads & Lookbehinds)

الفحوصات المحيطية هي **تأكيدات صفرية العرض (Zero-Width Assertions)**: تطابق موقعاً معيناً في النص *دون* أن تستهلك الحروف أو تدرجها ضمن النتيجة المستخرجة.

```
+---------------------------+----------------+------------------------------------------------+
| نوع الفحص المحيطي         | الصيغة النحوية | ينجح الشرط إذا كان:                            |
+---------------------------+----------------+------------------------------------------------+
| Positive Lookahead (أمامي)| (?=pattern)    | ما يلي هذا الموقع يطابق النمط pattern          |
| Negative Lookahead        | (?!pattern)    | ما يلي هذا الموقع لا يطابق النمط pattern       |
| Positive Lookbehind (خلفي)| (?<=pattern)   | ما يسبق هذا الموقع يطابق النمط pattern         |
| Negative Lookbehind       | (?<!pattern)   | ما يسبق هذا الموقع لا يطابق النمط pattern      |
+---------------------------+----------------+------------------------------------------------+
```

### أمثلة عملية برمجية:
```javascript
// 1. استخدام Positive Lookbehind لاستخراج الأسعار مجردة من رموز العملات:
const priceText = 'سعر المنتج الأول $150 وسعر الثاني €140';
const prices = priceText.match(/(?<=\$|€)\d+/g);
console.log(prices); // ["150", "140"]

// 2. استخدام Positive Lookahead للتحقق الصارم من سياسة تعقيد كلمات المرور:
// الشروط: حرف صغير واحد على الأقل، حرف كبير، رقم واحد، وطول لا يقل عن 8 أحرف
const strongPasswordRegex = /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)[A-Za-z\d@$!%*?&]{8,}$/;
console.log(strongPasswordRegex.test('P@ssword123')); // true
console.log(strongPasswordRegex.test('weakpassword')); // false

// 3. استخدام Negative Lookahead لمطابقة كلمة "Java" فقط حين لا تتبعها كلمة "Script":
const langRegex = /\bJava(?!Script)\b/g;
console.log('Java and JavaScript are different'.match(langRegex)); // ["Java"]
```

## 🏷️ 4. مجموعات الالتقاط المسماة ومؤشرات المواقع (Named Groups)

تُغنيك المجموعات المسماة عن الاعتماد الهش على أرقام الفهارس غير الواضحة (`match[1]`, `match[2]`):

```javascript
const logEntry = '2026-11-08 [ERROR] انقطع الاتصال بقاعدة البيانات shard-04';

// الصيغة: (?<groupName>pattern)
const logRegex = /(?<date>\d{4}-\d{2}-\d{2})\s+\[(?<level>[A-Z]+)\]\s+(?<message>.+)/d;

const match = logRegex.exec(logEntry);

if (match) {
  // تفكيك الخصائص مباشرة من match.groups بأسماء معبرة:
  const { date, level, message } = match.groups;
  console.log({ date, level, message });
  // النتيجة: { date: '2026-11-08', level: 'ERROR', message: 'انقطع الاتصال...' }

  // مؤشرات البداية والنهاية الدقيقة في ES2022:
  console.log(match.indices.groups.level); // [ 11, 16 ]
}
```

## 💥 5. التراجع الكارثي والوقاية من هجمات ReDoS

تحدث ثغرة **حجب الخدمة بالتعابير النمطية (ReDoS)** عندما يحتوي النمط على **محددات تكرار متداخلة (Nested Quantifiers)** أو احتمالات مطابقة متداخلة وغامضة، مع إدخال نص طويل يطابق النمط في معظمه ولكنه يفشل في الحرف الأخير تماماً.

### الكارثة الحسابية: التعقيد الأسي $O(2^n)$
تأمل هذا النمط البرمجي الذي يبدو بريئاً للوهلة الأولى للتحقق من نصوص أبجدية تنتهي برمز تعجب:

```javascript
// ⚠️ نمط شديد الخطورة مصاب بثغرة ReDoS: تكرار متداخل ([a-zA-Z0-9]+)+
const evilRegex = /^([a-zA-Z0-9]+)+$/;

// عند فحص نص صحيح يستغرق الأمر 0.01 مللي ثانية فقط:
evilRegex.test('aaaaaaaaaaaaaaaaaaaaaaaaa'); 

// ❌ إدخال خبيث (Evil Payload): يطابق النمط في كل شيء باستثناء علامة التعجب في النهاية!
// بالنسبة لنص بطول 30 حرفاً فقط، يقوم المحرك بتجربة 2^30 (أكثر من مليار مسار تراجع فاشل)!
// evilRegex.test('aaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!'); // يجمد المتصفح وسيرفر Node.js لعدة دقائق كاملة!
```

```
شجرة استكشاف المسارات الفاشلة (التراجع):
                     (a+)
                  /        \
              (a)(a...a)  (aa)(a...a)
             /    \          /    \
           ...    ...       ...   ...
إجمالي المسارات للتحقق من الفشل: 2^N (شلل تام في خيط معالجة جافاسكريبت)
```

### استراتيجيات الدفاع والوقاية الصارمة من ReDoS:

1. **القضاء على المحددات المتداخلة:** لا تكتب أبداً أنماطاً تحتوي على تكرار داخل تكرار مثل `(a+)+` أو `(a*)*` أو `([a-z]+)*$`. اجعل التكرار في طبقة مسطحة واحدة:
   ```javascript
   // ❌ خطأ فادح: محددات متداخلة
   const badRegex = /^([a-z]+)+$/;

   // ✅ آمن تماماً: محدد واحد مسطح ومباشر
   const safeRegex = /^[a-z]+$/;
   ```

2. **تقييد طول المدخلات قبل التمرير للنمط (Input Bounding):** تحقق دائماً من أن طول النص يقع في حدود معقولة قبل معالجته بالـ RegExp:
   ```javascript
   function validateInput(str) {
     if (typeof str !== 'string' || str.length > 256) {
       return false; // رفض مباشر للمدخلات الضخمة قبل تشغيل المحرك
     }
     return sanitizedPattern.test(str);
   }
   ```

3. **استخدام أدوات الفحص الساكن (Regex Linters):** استخدام مكتبات مثل `safe-regex` في مسار الاختبارات لفحص الأنماط وتنبيه المطورين من التراجع الكارثي.

## 🚀 6. استخراج البيانات المتقدم باستخدام `matchAll`

عند الحاجة لاستخراج تطابقات متعددة تحتوي على مجموعات التقاط، تُرجع دالة `String.prototype.matchAll()` كائن تكرار (Iterator) يحمل تفاصيل كل مطابقة:

```javascript
const markdownText = 'تابعنا على [Google](https://google.com) و [GitHub](https://github.com)';

const linkRegex = /\[(?<text>[^\]]+)\]\((?<url>https?:\/\/[^\s)]+)\)/g;

for (const match of markdownText.matchAll(linkRegex)) {
  const { text, url } = match.groups;
  console.log(`تم العثور على رابط -> النص: "${text}"، الرابط: "${url}"`);
}
// المخرجات:
// تم العثور على رابط -> النص: "Google"، الرابط: "https://google.com"
// تم العثور على رابط -> النص: "GitHub"، الرابط: "https://github.com"
```

## 🧼 7. كود نظيف: مقارنة الأنماط الجيدة والسيئة (Good vs Bad)

```javascript
// ❌ سيء: إنشاء كائن RegExp جديد داخل حلقة تكرارية سريعة (إعادة ترجمة مكلفة)
function formatItems(items) {
  return items.map((item) => {
    const regex = new RegExp('[a-z]+', 'g'); // يترجم النمط في كل لفة!
    return item.replace(regex, '');
  });
}

// ✅ جيد: تعريف النمط كـ ثابت ثابت في أعلى الملف مرة واحدة فقط
const TOKEN_REGEX = /[a-z]+/g;

function formatItems(items) {
  return items.map((item) => item.replace(TOKEN_REGEX, ''));
}

// ❌ سيء: الاعتماد على أرقام الفهارس غير المفهومة للمجموعات
const [_, countryCode, phoneNumber] = match;

// ✅ جيد: استخدام المجموعات المسماة لجعل الكود ذاتي التوثيق
const { countryCode, phoneNumber } = match.groups;
```

## 📝 8. ملخص الدرس والخطوة القادمة

- تعتمد جافاسكريبت على **محرك NFA** الذي يقوم بالتراجع (Backtracking) عند فشل المطابقات النهمة.
- استخدم **الفحص المحيطي (Lookarounds)** للتحقق من الشروط دون استهلاك الأحرف في النتيجة.
- اعتمد على **المجموعات المسماة (`(?<name>...)`)** لكتابة كود واضح ومحمي من أخطاء الفهارس.
- احذر تماماً من ثغرات **ReDoS**؛ تجنب المحددات المتداخلة `(a+)+`، وافرض قيوداً صارمة على أطوال المدخلات.
- استخدم **`matchAll()`** بدلاً من حلقات `exec()` المعقدة للتعامل مع التكرارات المتعددة.
- في الدرس القادم، سنتناول **التجميع الحديث والـ Source Maps: أدوات البناء (Vite و esbuild)، الـ Minification وأمن النشر في بيئة الإنتاج**.
